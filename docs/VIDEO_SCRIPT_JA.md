# 動画撮影・編集台本（目標2分40秒、1〜3分以内）

動画タイトル：`PAI最終課題_daichira`

この台本は撮影計画です。実際のロボット映像は未撮影であり、説明図を動作実績の映像の代わりにしません。既存のWindows画面録画・動画編集機能で、GazeboとUbuntu端末を撮影します。新しい録画ソフトの導入は必須ではありません。

## 撮影前

1. Gazeboでロボットの周囲を確認し、前進→左30度→前進の短い動作を行える位置にする。障害物回避機能はない。
2. Gazebo起動端末、実行端末、Odometry確認端末を分ける。通知・個人名・メール・Windowsの個人フォルダ表示を撮影範囲から外す。
3. APIキー入力中は録画を停止するか、後でその区間全体をカットする。文字が非表示でも入力画面は作品説明に不要。
4. シミュレータと端末を並べ、拡大率を調整。正常なE2E走行を1回撮影する。API障害時は失敗記録を保持し、別テイクで撮り直す。
5. 0.1m・30度・0.1mの計画を自分で読み、周囲を確認してから実行する。

## 撮影用コマンド（Ubuntu、ロボットが動く操作は明示）

```bash
cd /workspace/PAI_final_project
source /opt/ros/humble/setup.bash
source /home/ubuntu/pai_final_build/install/setup.bash
python3 src/llm_plan_openrouter.py --ask-key \
  '10cm前進して、左に30度回転し、その後10cm前進してください'
```

`PLAN_FILE`に出た実際のパスを使い、計画を確認する。API障害時はそのテイクでは動かさない。

動作の実行（周囲を確認後）：

```bash
mkdir -p experiments/final_video
set -o pipefail
python3 src/task_executor.py /実際の生成ディレクトリ/plan.json --execute 2>&1 \
  | tee "experiments/final_video/execution_$(date +%Y%m%d_%H%M%S).log"
execution_code=${PIPESTATUS[0]}
echo "VIDEO_EXECUTOR_EXIT_CODE=$execution_code"
```

上の`/実際の生成ディレクトリ/plan.json`は、`PLAN_FILE`の実値に置き換える。正常終了はコード0、TASK_SUCCESS、全ステップ成功が必要。失敗を成功テイクとして使用しない。

別端末で停止後を観測する：

```bash
ros2 topic echo /odom --field twist.twist
```

数サンプル確認後にCtrl+C。録画にAPIキー、環境変数の内容、認証ヘッダーを表示しない。
